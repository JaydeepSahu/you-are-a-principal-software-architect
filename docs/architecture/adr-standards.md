# ADR Standards

This page defines standards for Architectural Decision Records (ADRs).

## Purpose

- Capture architecture decisions, context, and consequences.
- Maintain a searchable decision history.
- Align decisions with platform and enterprise requirements.

## Format

- Use the ADR template in `../adr/adr-template.md`.
- Keep ADRs short and structured.
- Include context, decision, alternatives, and consequences.

## Naming

- Use sequential ADR IDs: `ADR-0001`, `ADR-0002`, etc.
- Use a descriptive title after the identifier.
- Keep file names consistent with the ADR title.

## Process

- Create an ADR for decisions that affect architecture, security, or platform behavior.
- Review ADRs in PRs and keep them current.
- Reference ADRs from related documentation and release notes.
