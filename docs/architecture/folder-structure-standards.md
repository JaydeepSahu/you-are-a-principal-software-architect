# Folder Structure Standards

This page defines folder structure standards for the documentation portal and repository.

## Purpose

- Ensure documentation is organized and discoverable.
- Keep the repository layout intuitive for contributors.
- Maintain clear separation between documentation categories.

## Docs Folder Structure

- Use top-level folders for major categories such as `getting-started`, `architecture`, `api`, `deployment`, `security`, `observability`, `testing`, `operations`, `troubleshooting`, `adr`, and `diagrams`.
- Use `assets` for supporting images and files.
- Use `index.md` as the landing page for each category.

## Naming

- Use lowercase names and hyphens for directory names.
- Keep folder names brief and descriptive.

## Maintenance

- Add new categories only when there is a clear need.
- Keep related docs grouped within the same folder.
- Review the folder structure when adding major new content areas.
